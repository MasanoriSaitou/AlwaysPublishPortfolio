?? AIコード生成専用・最強プロンプトテンプレート集

AI（特にGeminiなどの大規模言語モデル）から、エラーが少なく、意図した通りの高品質なソースコードを1発（または最小限のラリー）で引き出すためのプロンプトテンプレートとガイドラインです。

?? 1. 【基本】ゴールデン・プロンプト・テンプレート

あらゆるプログラミング言語・フレームワークに使える、最も汎用性が高く高精度な基本構成です。以下の構造で依頼を投げると、AIは迷わずに最適なコードを組み立てられます。

# 役割・前提

ユーザー（私）の要望を元に、クリーンで保守性の高い、バグのないコードを生成してください。

# 目的
[何を作るのか、最終的なゴールを1?2行で記述]
（例: 個人開発で使う、タスク管理のためのシンプルなシングルページアプリケーションを作りたい。）

# 技術スタック・環境
- 言語: [例: TypeScript, HTML5, Python 3.11...]
- フレームワーク/ライブラリ: [例: React (Vite), Tailwind CSS, Express...]
- 外部API/依存関係: [例: なし（インラインSVGを使用、外部アイコンライブラリは使用しない）]

# 実装したい機能・仕様

# 制約事項（重要！）
- [制約1: 例: すべてのコンポーネント、ロジック、スタイルを「1つのファイル」にまとめること]
- [制約2: 例: TypeScriptの型定義（Interface）を100%明示し、any型は使用しないこと]
- [制約3: 例: 外部依存（npm installが必要なライブラリ）は最小限にし、可能な限りピュアなコードで書くこと]

# 出力フォーマット
- コードブロックで、コピペしてすぐ動く完全なコードを出力してください。
- 重要な処理や複雑なロジックには、丁寧な日本語のコメントを添えてください。

## ?? 3. AIに「最高の回答」を出させる5つの黄金則

AIと開発する際に、以下の5つのポイントを意識するだけで、生成されるコードの品質が3倍以上変わります。

| 黄金則 | 具体的なアクション | なぜ効果があるのか？ |
| :--- | :--- | :--- |
| **1. 制約を先に課す** | 「外部ライブラリを絶対に使わない」「TypeScriptの型を省略しない」など、最初に**禁止事項**を明確にする。 | AIはデフォルトでは「便利な外部ライブラリ（lucide-reactなど）」を勝手に使おうとして、ローカル環境でのビルドエラーの原因を作るため。 |
| **2. 環境を正確に伝える** | 「Vite + TypeScript の環境です」「TailwindはCDNで読み込みます」など、前提環境を伝える。 | AIがローカル環境に合わせた最適（ESモジュール形式かCommonJS形式かなど）な設定や書き方を選択できるようになるため。 |
| **3. 動く最小単位から作る** | 一気に巨大なアプリを作らせず、「まずはタイトル画面と基本ロジック」「次に戦闘」「次にショップ」と**段階的に拡張**する。 | 1回に出力できる文字数（トークン数）の制限によるコードの途切れを防ぎ、ロジックのバグを最小限に抑えられる。 |
| **4. エラーは「丸ごと」渡す** | 自分の解釈を挟まず、エラーログ（TerminalやBrowserのConsole）を**そのままコピーして渡す**。 | エラーログにはスタックトレース（どこのファイルの何行目で、なぜ落ちたか）のすべてが含まれており、AIが最も得意とする解析情報だから。 |
| **5. ファイルの集約を命じる** | 開発初期フェーズでは「**すべてを1ファイルにまとめて出力して**」と指示する。 | 複数ファイルに分割されると、インポートのパスのズレや、ファイルの作成忘れなどのローカルエラーが多発するため。まずは1ファイルで完璧に動くものを作り、後からリファクタリングで分割するのが開発の定石です。 |

---

このテンプレートを「プロンプトの骨組み」として使い、`[ ]` の部分を毎回書き換えてAIに送信してみてください。驚くほど正確で、すぐに手元で動くコードが返ってくるようになります！
